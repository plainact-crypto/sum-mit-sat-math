# SUMMIT Explanation Standard — Graphs + Desmos

This file is the authoritative standard for every SUMMIT Explanation page, both new and retrofitted.

## 1. Required classification before writing
Every Explanation must be classified as exactly one of:
- GRAPH_REQUIRED
- DESMOS_USEFUL
- BOTH
- NEITHER

For the retrofit/build registry, `GRAPH` is the machine-readable equivalent of `GRAPH_REQUIRED` and `DESMOS` is the machine-readable equivalent of `DESMOS_USEFUL`.

Do not force a graph or Desmos block into lessons where it adds no learning value.

## 2. Graph rule
When a graph is required, the graph must be generated from the underlying mathematics, never drawn as an AI image and never approximated visually.

The equation/function/table is the source of truth. The rendered graph must be deterministic and reproducible from the math.

Required graph QA:
- Axes and scale are appropriate for the problem.
- Every plotted curve/line corresponds exactly to the stated equation/function.
- Any labeled point, intercept, root, vertex, endpoint, or intersection is independently calculated and verified.
- For linear functions, independently verify at least 3 points by substitution before publish.
- For systems, independently solve the system and verify the plotted intersection.
- For quadratics, independently verify vertex/roots/intercepts when shown.
- For piecewise/domain-restricted functions, enforce the exact restrictions.
- No fake Desmos screenshot and no decorative graph that is not mathematically tied to the lesson.

Preferred implementation: native interactive or deterministic SVG/canvas graph generated by site code from structured mathematical data. PNG/JPG graph screenshots are not the default.

## 3. Desmos Strategy block
When Desmos is useful, add a clearly labeled section named `DESMOS STRATEGY` with this structure:

1. `Enter` — exactly what the student should type.
2. `Look for` — what visual/value/result to identify.
3. `Use it to answer` — how the observed result answers the question.
4. `Why it works` — one concise conceptual explanation connecting the tool to the math.
5. `Faster or not?` — explicitly state whether Desmos is actually the faster route for this type of question.

The Desmos instructions must be specific to the lesson. Do not insert generic boilerplate.

## 4. Desmos QA
Before publish:
- Every expression to be entered must be mathematically valid.
- Every expected Desmos result must be independently verified without relying on Desmos output alone.
- If an intersection is referenced, solve it algebraically as a cross-check.
- If a root/zero is referenced, substitute it into the original equation.
- If a regression/table workflow is used later, verify the data and model independently.
- Never invent a shortcut or claim Desmos can do something that has not been verified.

## 5. Explanation structure
Keep the approved SUMMIT explanation flow, and insert visual/tool support where pedagogically appropriate. A typical order is:
1. Learning objective
2. Core concept/rule
3. Worked example(s)
4. Graph/visual block when required
5. Desmos Strategy when useful
6. Common mistakes / exam strategy
7. Quick check / recap

Graph and Desmos blocks are adaptive, not mandatory in every lesson.

## 6. Content philosophy
Students should understand the mathematics first and also know when a graphing tool gives a faster or safer route. Desmos is a strategy layer, not a replacement for concept understanding.

## 7. Publish gate
An Explanation is not complete if it was classified GRAPH_REQUIRED or BOTH and the verified graph is missing. It is not complete if classified DESMOS_USEFUL or BOTH and the verified Desmos Strategy block is missing.

## 8. Implementation contract for all future Explanations
`explanation-retrofit-registry.js` is the machine-readable source of truth for every published Explanation. Before a new Explanation can become published content, its worker must add or update exactly one registry entry containing:
- stable slug
- exact lesson title
- one classification
- deterministic graph specification when GRAPH/BOTH
- lesson-specific Desmos strategy when DESMOS/BOTH

`explanation-retrofit-build.js` applies the required blocks to the built route without rewriting correct lesson prose. `explanation-retrofit-gate.js` rejects a build when a published Explanation is absent from the registry, duplicated, missing its classification marker, missing a required graph, missing a required Desmos block, or violates a special graph relationship rule.

This means no future published Explanation may create new Graph/Desmos retrofit debt.
