Solving from Tables
Algebra
01 · LESSON OBJECTIVE

Find the common ordered pair directly from two tables.

When two linear relationships are shown as tables, the solution to the system is the input-output pair that appears in both relationships. You should also be able to verify that shared pair using equations or a graph.

Table A and Table B share→(2, 5)
02 · WHAT YOU NEED TO KNOW

A system solution must satisfy both relationships at the same time.

In a table, each row is an ordered pair. Compare the rows from both tables using the same x-value. If both tables produce the same y-value, that ordered pair is the solution.

Same xcompare outputsUse matching inputs first.
Same y tooshared rowThat ordered pair satisfies both relations.
Different ynot the solutionThe two relationships disagree at that input.
No shared row shownextend or modelUse the pattern or equation if needed.
03 · KEY DEFINITIONS

System

Two equations or relationships considered together.

Solution

An ordered pair that makes both relationships true.

Intersection

The graph point shared by both lines.

04 · CORE RULE

Match x-values, then look for equal y-values.

SAME x + SAME y = SYSTEM SOLUTION
05 · HOW IT WORKS

Use a row-by-row comparison.

01
Scan for common x-values.Do not compare rows with different inputs.
02
Compare the corresponding y-values.Equal outputs mean both relationships contain that point.
03
Write the ordered pair.Use the form (x, y), not just one coordinate.
04
Verify if needed.Substitute into equations or confirm the graph intersection.
06 · WORKED EXAMPLE 1 — DIRECT MATCH

Compare the two tables.

Table A: (0,1), (1,3), (2,5), (3,7)Table B: (0,7), (1,6), (2,5), (3,4)At x=2, both tables give y=5.Solution: (2,5)
WhyThe same ordered pair belongs to both relationships.
07 · WORKED EXAMPLE 2 — BUILD THE PATTERN

What if the shared row is not immediately obvious?

Table A y-values rise by 2 when x rises by 1 → y=2x+1Table B y-values fall by 1 when x rises by 1 → y=−x+72x+1=−x+7 → 3x=6 → x=2y=2(2)+1=5
Solution(2,5)
08 · WORKED EXAMPLE 3 — NO MATCH IN THE DISPLAYED ROWS

The tables show x=0,1,2 only, but the patterns continue.

If no displayed row matches, do not conclude “no solution” automatically. First decide whether the table represents a continuing linear pattern. Extend the pattern or write equations, then solve.

ImportantA missing displayed intersection is not the same as a system with no solution.
09 · WORKED EXAMPLE 4 — EXAM-STYLE

Two plans are summarized by tables. At what input do their totals first match?

Plan A: (1,14), (2,18), (3,22), (4,26)Plan B: (1,20), (2,18), (3,16), (4,14)The shared row is (2,18).
Answer the requested quantityThe input is 2.
10 · WHY THE GRAPH MATCHES

The common table row becomes the graph intersection.

For the model y=2x+1, the points include (0,1), (1,3), and (2,5). For y=−x+7, the points include (0,7), (1,6), and (2,5). The lines therefore meet at (2,5), exactly matching the shared row.

11 · COMMON MISTAKES
Matching only the y-value

The x-value must also be the same. A solution is one ordered pair.

Comparing different x-values

Line up equal inputs before comparing outputs.

Assuming no displayed match means no solution

The intersection may occur outside the rows shown.

Giving only x when the question asks for the system solution

Return the ordered pair unless a different quantity is requested.

12 · EXAM STRATEGY

Use the table first; algebra is the backup.

If a shared row is visible, reading it is usually faster than solving equations. If the shared row is not shown, identify the linear pattern and solve the corresponding equations.

14 · LESSON RECAP

A table solution is simply the point both relationships share.

  1. Match equal x-values.
  2. Compare the y-values.
  3. Equal outputs identify the shared ordered pair.
  4. If no match is displayed, extend the pattern or write equations.
  5. Use algebra or a graph to verify when useful.
